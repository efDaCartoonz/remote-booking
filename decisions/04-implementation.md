# Техническая реализация

## Решения

- MVP — модульное приложение, а не микросервисная архитектура.
- Стек: FastAPI, Vue 3/Vite, PostgreSQL, Redis, Celery и Alembic; запуск описан в `docker-compose.yml`.
- Readiness должен проверять реальную доступность PostgreSQL и Redis, а не только процесс backend.
- Секреты не хранятся в открытом виде и не попадают в репозиторий.
- Работу вести по порядку технического проекта: миграции и локальная авторизация → карточка/статусы → Frame API → распределение → действия L1/L2 → Omnidesk и уведомления → stage-проверка.

## Статус реализации на 24 сентября 2026

Исходный порядок работ выполнен до IE-01 включительно: в `main` есть карточки,
авторизация, Frame API, распределение, действия ролей и исходящий Omnidesk
outbox. Сверка кода выявила два corrective для BL-04 и IE-01; после их
исправления и повторных gates планируется IE-02. Точные границы и результаты
записаны в `Docs/RDM-ROADMAP.md`; stage-проверка IE-01 не подтверждена.

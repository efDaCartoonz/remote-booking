# 12. Тестовый стенд без зависимости от интеграций: создание карточки без проверки в Omnidesk

Принято владельцем продукта 1 октября 2026 г.: на этом этапе функциональность проверяется
без зависимости от интеграций, карточки создаются без проверки тикета в Omnidesk.

## Правило

Флаг `OMNIDESK_TICKET_VERIFICATION_ENABLED` (по умолчанию `true`, на стенде `false`).
При `false` создание карточки (L1, L2-самосоздание, руководитель) и предпроверка тикета руководителя:

- принимают публичный номер `NNN-NNNNNN` как введён; формат проверяется, существование нет;
- не читают индекс `omnidesk_case_index`, не вызывают API Omnidesk, **не переоткрывают закрытые тикеты**;
- не привязывают клиента (`client_id = NULL`), имя клиента неизвестно;
- сохраняют остальные проверки: окно времени, длительность, одна активная карточка на тикет,
  права ролей, автоназначение, графики, отсутствия, календарь;
- предпроверка руководителя возвращает статус `unverified` и `can_create = true`, если нет активной карточки.

Внутренний `case_id` по-прежнему не используется и не раскрывается. Исходящие записи (outbox)
по-прежнему ставятся в очередь по номеру тикета и находят `case_id` в момент доставки;
при выключенной доставке они только копятся.

## Возврат к проверке

Установить `OMNIDESK_TICKET_VERIFICATION_ENABLED=true`: прежнее поведение (индекс, ленивое
заполнение, чтение тикета, переоткрытие закрытого) не менялось и покрыто прежними тестами.
Карточки, созданные без проверки, остаются без клиента.

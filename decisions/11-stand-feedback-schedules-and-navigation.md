# 11. Обратная связь по тестовому стенду: графики по датам, навигация, поиск тикета

Принято владельцем продукта 1 октября 2026 г. по итогам ручной проверки FE-04 на
стенде RPi. Решение новее SRS (`ADM-*`, `UI-046`, `API-018`) и при конфликте
имеет приоритет. Перенос в SRS и Technical Design — отдельный шаг документатора.

## Графики работы

- Рабочее время сотрудника задаётся **по датам**, без недельной закономерности:
  один рабочий интервал в день, без разрывов и без смен через полночь.
  День без интервала — выходной. Допустимы графики вида «2/2» и произвольные.
- Хранение: существующая таблица `schedules`; смена на дату — строка с
  `valid_from = valid_to = <дата>` и `weekday` этой даты. Схема не менялась,
  логика распределения и признак «вне рабочего времени» читают такие строки как есть.
  Одна смена в день обеспечивается API (`schedule_duplicate_day`).
- API: `GET /api/v1/admin/schedules/days`, `GET /api/v1/admin/schedules/employees`,
  `PUT /api/v1/admin/schedules/{user_id}/days` (замена диапазона до 93 дней),
  права — администратор и руководитель. Первое сохранение по датам удаляет
  прежние недельные строки сотрудника (реальных данных нет, см. память проекта).
- Инструмент руководителя: сетка «сотрудники × дни месяца», правка ячейки,
  шаблоны (каждый день, по дням недели, N/N), копирование прошлого месяца.
  Страница `/schedules`, также вкладка в администрировании.
- Производственный календарь **остаётся** и сохраняет действующую роль:
  в нерабочие даты нет автоназначения, карточки получают признак «вне рабочего
  времени». Дополнительно он служит подсказкой при составлении графика: такие дни
  подсвечены, шаблоны по умолчанию не ставят на них смены. Сам график он не меняет.

## Участие в распределении

Оставлено: сотрудник с графиком может быть исключён из автоназначения
(например, занят на удалённых подключениях). Это не отсутствие. Основание при
изменении остаётся обязательным и пишется в журнал (ранее принятое решение).

## Справочники

Раздел «Справочник результатов» убран из интерфейса администратора.
Значения в БД и выбор результата при завершении карточки сохраняются; API
управления справочником остаётся. Возврат раздела — отдельным патчем при
необходимости. Остальные перечисления (`dict_values`) системные и не
редактируются. Справочники причин отказа, отмены и переноса не вводятся:
причины — свободный текст.

## Поиск тикета по номеру

Omnidesk API не умеет фильтровать обращения по `case_number` (проверено по
документации `GET /api/cases.json`), а номер не совпадает с `case_id`
(проверено на реальной паре). Поэтому локальный индекс `omnidesk_case_index`
остаётся: хранится только `case_id`, номер, клиент и статус.

- Индекс заполняется **лениво**: при промахе backend читает недавно изменённые
  обращения (`from_updated_time`, по умолчанию 7 дней, до 5 страниц по 100) и
  сохраняет увиденное. Промах кэшируется на 60 секунд.
- Настройка: `OMNIDESK_CASE_LAZY_LOOKUP_ENABLED` (по умолчанию выключена),
  `OMNIDESK_CASE_LAZY_LOOKUP_DAYS`, `OMNIDESK_CASE_LAZY_LOOKUP_MAX_PAGES`.
- Ограничение: обращение старше окна не найдётся без ручного backfill
  (`backend/scripts/omnidesk_case_backfill.py`). Вебхуки — для боевого контура.
- `case_id` по-прежнему не попадает в браузер, URL, ошибки и логи.

## Интерфейс

- Навигация: левая колонка разделов, справа — открытый раздел (роль определяет
  набор пунктов). Часовой пояс профиля перенесён на страницу «Профиль».
- Выбор даты и времени: выпадающие списки допустимых дат и времени с шагом
  15 минут в границах окна планирования (минимальное время до подключения,
  горизонт — из настроек, `GET /api/v1/cards/planning-window`).
- Отсутствия по умолчанию: 00:00–23:59.
- В администрировании у каждого раздела краткое пояснение; для шаблонов
  уведомлений — список подстановок.

## Демо-данные

`backend/scripts/seed_demo.py` создаёт синтетических пользователей `demo-*`,
графики, клиентов и карточки за 30 дней (все помечены `DEMO`), `--remove`
удаляет ровно их. Внешние системы не затрагиваются.

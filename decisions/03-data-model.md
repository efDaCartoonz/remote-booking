# Данные и хранение

## Решения

- Внутренние идентификаторы — числовые; внешний идентификатор карточки — `public_id uuid`.
- Значения справочников хранятся в `dict_values` с парой `(sysname, code)`; устаревшие значения скрываются, а не удаляются.
- `connection_cards.number` формируется последовательностью в виде `RDM-000001`.
- В карточке хранится плановое начало и длительность; плановое окончание вычисляется. Фактические начало и окончание сохраняются для истории.
- Контакт клиента — пара `client_contact_type_code` и `client_contact_value`.
- В первой схеме MVP нет таблиц `omnidesk_tickets`, `frame_sessions`, `engineer_reservations`, `outbox_events` и отдельной таблицы результатов подключения. Последующие миграции добавили специализированный Omnidesk outbox и каталог результатов; актуальную схему определяет Alembic.
- Сессия клиентского фрейма хранится в Redis с TTL по ключу `frame_session:{token_hash}`.

## Важная проверка

Ограничения и seed-данные из первой Alembic-миграции нужно применить на чистой PostgreSQL базе до объявления схемы готовой для stage.

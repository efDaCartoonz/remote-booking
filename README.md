# Remote Desktop Manager (RDM)

RDM — приложение для планирования и сопровождения удалённых подключений. Оно
хранит карточки подключений, распределяет работу между специалистами первой и
второй линии, помогает руководителю следить за загрузкой команды и сохраняет
историю действий. Omnidesk остаётся системой обращений, а RDM управляет
процессом подключения.

## Возможности

- Создание карточек и работа с их жизненным циклом по ролям L1, L2 и
  руководителя.
- Планирование подключений с учётом расписаний, отсутствий и занятости
  специалистов.
- Список и календарь подключений для руководителя.
- Клиентский API для создания карточки из контекста обращения Omnidesk.
- Внутренние уведомления через Telegram и Битрикс24, исходящие действия в
  Omnidesk.
- История событий и аудит изменений карточек.

Состав реализованных сценариев и известные ограничения описаны в
[дорожной карте](Docs/RDM-ROADMAP.md). Проект находится в разработке;
готовность отдельных функций к эксплуатации следует проверять по ней.

## Технологии

Backend написан на Python с FastAPI и PostgreSQL. Фоновые задачи выполняются
Celery с Redis. Интерфейс построен на Vue 3 и Vite. Для локального запуска
используется Docker Compose.

## Локальный запуск

Понадобятся Docker с поддержкой Compose и `make` для запуска проверок.

1. Скопируйте `.env.example` в `.env` и задайте собственные локальные пароли и
   `APP_SECRET_KEY`. Для интеграций заполните соответствующие параметры
   Omnidesk, Telegram и Битрикс24. Не добавляйте `.env` в Git.
2. Создайте схему базы данных и запустите приложение:

   ```bash
   docker compose run --rm backend alembic upgrade head
   docker compose up --build -d
   ```

3. Откройте интерфейс по адресу [localhost:8080](http://localhost:8080).
   API и его документация доступны на [localhost:8000/api/docs](http://localhost:8000/api/docs).
   Проверка состояния сервиса: [localhost:8000/health/ready](http://localhost:8000/health/ready).

Для входа нужна внутренняя учётная запись RDM; миграции не создают пользователя
по умолчанию. Доставка внешних уведомлений и периодическое сканирование в
примере конфигурации выключены.

## Проверки

Команда `make verify` запускает тесты backend и frontend, проверки стиля,
конфигурации Compose и миграций. Для запуска отдельных частей используйте
`make verify-backend`, `make verify-frontend`, `make verify-compose` или
`make verify-migrations`.
